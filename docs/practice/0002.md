# 2. Add Two Numbers

You are given two non-empty linked lists representing two non-negative integers. The digits are stored in reverse order, and each of their nodes contains a single digit. Add the two numbers and return the sum as a linked list.

You may assume the two numbers do not contain any leading zero, except the number 0 itself.

=== "Example 1"

    - Input: l1 = [2, 4, 3], l2 = [5, 6, 4]
    - Output: [7, 0, 8]
    - Explanation: 342 + 465 = 807.

=== "Example 2"

    - Input: l1 = [0], l2 = [0]
    - Output: [0]


=== "Example 3"

    - Input: l1 = [9, 9, 9, 9, 9, 9, 9], l2 = [9, 9, 9, 9]
    - Output: [8, 9, 9, 9, 0, 0, 0, 1]

## Solution

??? "Expand"

    3ms, beats 23.6%

    ```kotlin linenums="1"
    fun addTwoNumbers(l1: ListNode?, l2: ListNode?): ListNode? {
      // Check if either of the number is empty, if so return the other
      if (l1 == null && l2 == null) return null
      if (l1 == null) return l2
      if (l2 == null) return l1
      
      // Shadow l1 and l2 so they can be made variable instead of constant
      var l1 = l1
      var l2 = l2

      // Use the first list as outout
      val head = l1
      var tail: ListNode? = l1

      var carry = 0
      while (l1 != null || l2 != null || carry > 0) {
        val sum = (l1?.`val` ?: 0) + (l2?.`val` ?: 0) + carry
        tail!!.`val` = sum % 10
        carry = sum / 10

        l1 = l1?.next
        l2 = l2?.next

        // Same check as above. We use this to lay track as we proceed.
        // https://youtu.be/hDbMmFYyRzo?t=61
        if (l1 != null || l2 != null || carry > 0) {
          if (tail.next == null) {
            tail.next = ListNode(0)
          }
        }
        tail = tail.next
      }
      return head
    }
    ```

??? "Expand"

    2ms, beats 86.34%

    The culprit here isn't the elvis `?:` operator. Rather it's the autoboxing. Since `l1?.val` can be null, the compiler is required to return an `Int?` which becomes `java.lang.Integer` in JVM.

    The Kotlin compiler generates JVM bytecode that does something like this under the hood:

    1. Check if `l1` is null.

    2. If not null, read `l1.val` (primitive int).

    3. Box it: Create a new `java.lang.Integer` object on the heap to hold that primitive, just in case it needs to be passed as null.

    4. Apply the Elvis operator `?:` Check if the Integer object is null.

    5. Unbox `.intValue()` to extract the primitive int back out to do the math.

    6. Repeat all of this for `l2`.

??? "Expand"

    1ms, beats 100%

    In Kotlin, `!!` inserts a hidden runtime `Intrinsics.checkNotNull()` check into the bytecode.

    In a long-running server application, the JVM's Just-In-Time (JIT) compiler would eventually realize that tail is never null. It would optimize the code, inline the `checkNotNull` method, and eventually strip it out completely, meaning `tail!!` would have zero overhead.

    However, in an online judge, the execution is over in a few milliseconds. This means the JVM never fully "warms up." It executes the code using the basic interpreter or the lower-tier compiler. Therefore, for every single node in the linked list, the code was actively making a method call to `Intrinsics.checkNotNull()`.
